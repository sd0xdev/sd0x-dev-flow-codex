# Native stacked pull requests

Select report, link, push or submit from the explicit request; default is read-only report. Preserve the exact repository, remote, explicit base and ordered bottom-to-top chain throughout investigation and any delegation. Resolve explicit branch names or full PR URLs to that repository; bare numbers are not branch operands. Otherwise inspect the tracked chain and require one unambiguous match for the current branch. Never infer another base after an analysis rerun.

Read the active Git action and project-policy contracts. Inspect extension identity/version read-only, using installed extension metadata and executable hash. The reviewed upstream reference is github/gh-stack v0.1.1. Do not silently install/upgrade an extension; prepare its exact repository/version and obtain any missing external-install authority. Native operations below do not depend on extension installation. Do not use extension view as a read-only probe: it may change local tracking state.

Collect local OIDs, exact remote OIDs via read-only remote query, ancestry, all matching PRs (including closed/merged), readiness, base, title/body, merge queue, auto-merge, Stack API state and local tracking bytes. Read modify-state and reject any pending modification for mutations; never invoke an implicit unstack/delete recovery. Treat ambiguous/multiple PRs and incomplete pagination as unresolved. No auth error or HTTP 404 proves absence.

Prepare a native workflow stack-plan request with options: mode, repository (owner/name), remote, base, tracked boolean and tracked_sha256, open boolean, and ordered layers containing head, local_oid, remote_oid (null only after successful absence query), pr (number or null), fast_forward, active, title and body. The helper reads the real project policy, pins every layer/lease and preserves base. Merged/queued layers are recorded as skipped. Protected layer mutations are rejected. Report mode performs no mutation. The plan is scope, not authority.

For link, use the prepared exact OID refspecs in one atomic Git push; reject non-fast-forward targets. For push, perform only approved active layer pushes using their literal exact leases. For submit, push the tracked active layers, then prepare each PR through the single-PR title/body sanitization and publication procedure. This native transport replaces v0.1.1's fetch-then-lease behavior: never call its push/submit commands, which can change the expected remote tip after preview. A native non-fast-forward push still requires explicit overwrite authority and a reconciled expected tip; neither mode grants it. Refuse force deletion, implicit unstack or any action outside the preview.

For link/submit preview every new or updated PR, its exact base, draft/open change, sanitized title/body and payload hash. Default new PRs to draft. open explicitly covers readiness changes on existing layers. Submit also previews disabling auto-merge; apply that change only within authorized scope. Preserve useful user-authored PR content. Revalidate remote identity/OIDs, local OIDs, tracking digest and PR state immediately before each mutation; do not refresh an approved lease silently.

After PRs exist with the verified ordered bases, native Stack creation uses stack-api-plan(repository, numbers); appending to a confirmed existing stack uses its number and only the newly added top PR numbers. The result provides fixed gh API argv and JSON stdin (pull_requests numbers). Do not duplicate a Stack on unknown state, reorder existing members or drop additional PRs. Arguments and JSON stdin remain literal, without shell interpolation. Each external mutation still needs actual user authority for its exact payload.

After any success or failure re-query every layer's remote tip and PR fields, and GET repos/{owner}/{repo}/stacks?pull_request={number} for each PR. Feed actual complete results to stack-observe; HTTP 200 empty lists or successful no-PR queries can establish confirmed-absent. A confirmed Stack requires one identical ordered chain across all responses; report additional PRs. The stack-outcome request contains mode, actual exitCode, observation, expected field records and actual records with read_ok. Exit zero alone is never completion. Report complete, partial, failed-existing-stack, published/pushed-without-stack or unverifiable exactly as supported.

A hand-built chained-base fallback is allowed only after confirmed absence, a fresh complete PR re-query and authority for each remaining concrete action. Label it ordinary dependent PRs, not native Stack success. Never fall back or retry after an unverifiable result, existing Stack failure or partial readback. Sanitize and verify attribution on every changed layer; preserve partial publication evidence. No external writes are required to test this workflow: tests rely on isolated Git fixtures and recorded API cases, explicitly labeling live publication untested.

Publication includes a push operation and, for an explicitly selected non-fast-forward update, a history-rewrite operation. PR and Stack publication remains a pr-write operation. These capability declarations never grant execution scope.
